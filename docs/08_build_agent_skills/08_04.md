# Task 04 - Test and refine the skill

## Introduction

Test whether `blue-brand-pptx` can combine the PDF-derived style and bundled assets with a new presentation brief. Inspect the rendered slides, not just the generation script.

## Description

Create a short presentation about **"compare GPT-6.1-sol with Claude Opus 5.5"**. Treat these as the requested model labels, not proof of public availability or published capabilities. Verify claims using current primary sources.

## Success Criteria

- A PPTX and rendered slide previews are generated using `blue-brand-pptx`.
- Slides follow the approved PDF-derived style and demonstrate appropriate use of the extracted assets.
- Model claims have dated sources; unavailable information is labeled as unverified, not fabricated.
- Every slide is inspected, and any fixes are regenerated and rechecked.

## Learning Resources

- [Agent skills in VS Code](https://code.visualstudio.com/docs/agent-customization/agent-skills)
- [W3C accessibility fundamentals](https://www.w3.org/WAI/fundamentals/accessibility-intro/)

## Key Tasks

1. Start a fresh Copilot chat so the updated skill can be discovered. Explicitly request `blue-brand-pptx`:

   ```text
   Use the blue-brand-pptx skill in .agents/skills/blue-brand-pptx
   to create a five-slide presentation about:
   "compare GPT-6.1-sol with Claude Opus 5.5".

   First read SKILL.md, references/brand-style.md, and assets/README.md.
   Apply the approved PDF-derived style and reuse suitable extracted
   icons/images from the skill folder. If those references are missing,
   stop and request the customer sample PDF instead of inventing a style.

   Slides:
   1. Title and comparison scope.
   2. Verified model identity, availability, and source dates.
   3. Side-by-side capabilities and limitations.
   4. Developer use cases and evaluation criteria.
   5. Trade-offs, unknowns, and recommended next evaluation steps.

   Use current official sources and add source URLs and access dates
   in speaker notes. Do not invent benchmark scores, pricing, context
   limits, or capabilities. If either exact model label is not documented,
   mark its details "unverified" and describe what evidence is missing.
   Do not silently substitute another model or declare an unsupported winner.

   Save the deck as workshop-output/blue-brand-model-comparison.pptx.
   Render slide previews using the skill's documented tools and inspect
   every slide for overlap, clipping, contrast, and brand consistency.
   Report missing prerequisites or generation/rendering errors explicitly.
   ```

2. Verify Copilot used the new skill rather than only the original `pptx`. Check the resulting deck against the style guide and reference PDF.
3. Review all five rendered slides and open the PPTX in PowerPoint or a compatible viewer:
   - Colors, typography, spacing, backgrounds, and footers match the approved rules.
   - Extracted icons/images retain quality and aspect ratio and are used appropriately.
   - Text is readable, contrast is sufficient, and nothing overlaps or extends off-slide.
   - Sources support the exact model labels and claims; unknowns remain visible.
   - Speaker notes retain the source URLs and dates.
4. If you find an issue, improve the relevant reusable rule in `blue-brand-pptx`, regenerate the deck, and inspect the affected slides again. Do not change the original skill.
5. Share the skill and output only through an approved channel after checking licenses, asset permissions, and sensitive content. Keep customer-specific materials out of the reusable workshop repository.

## Expected Deliverables

- The independent `.agents/skills/blue-brand-pptx` skill with a PDF-derived style guide and approved asset inventory.
- `workshop-output/blue-brand-model-comparison.pptx` and rendered previews.
- A brief review summary covering style fidelity, factual sources, extraction limitations, and any corrections.
