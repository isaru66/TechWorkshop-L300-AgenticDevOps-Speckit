# Task 03 - Explore the spec-driven workflow

## Introduction

Spec-driven development separates the desired outcome from its technical implementation.

## Description

Explore the generated integration and the steps for establishing project principles, specifying a feature, planning, and creating tasks.

## Success Criteria

- You can distinguish a specification from an implementation plan and a task list.
- You know that Spec Kit skills run in the agent chat after initialization, not as terminal commands.

## Learning Resources

- [Spec-driven development quickstart](https://github.github.io/spec-kit/quickstart.html)

## Key Tasks

### 1. Inspect the initialized workspace

Use VS Code Explorer and Source Control to inspect the files generated in Task 02. Identify the Spec Kit templates, scripts for your selected script type, and Copilot integration files. File organization can vary across releases, so use the generated files in your workspace as the reference.

### 2. Identify the workflow skills

In GitHub Copilot Chat, type `/speckit` and inspect the available entries. The screenshot in [Task 02]({% link docs/03_spec_kit_fundamentals/03_02.md %}#6-verify-the-spec-kit-skills) shows the hyphenated skill names used in this workshop.

| Skill | Purpose | What to review |
|---|---|---|
| `/speckit-constitution` | Establish or update project principles and constraints. | The rules that later specifications and plans must follow. |
| `/speckit-specify` | Describe the desired feature and user outcomes. | Shared requirements, user scenarios, and success criteria, rather than backend implementation details. |
| `/speckit-clarify` | Resolve underspecified areas of the specification. | Questions and decisions that remove ambiguity before planning. |
| `/speckit-plan` | Turn the specification into a technical implementation plan. | The selected backend technology and how the requirements will be implemented. |
| `/speckit-tasks` | Break the plan into actionable, dependency-ordered tasks. | The work items that guide implementation. |
| `/speckit-implement` | Execute the implementation tasks. | Code changes and validation against the specification and plan. |

These are chat skills, not terminal commands. Inspect them now; the next exercise begins the feature specification and planning work.

### 3. Carry the workshop boundaries forward

Keep the next exercise's banking scenario fictional and local-only. Use synthetic data, not real customer data or credentials, and do not connect to real banking systems. Carry these constraints into project principles, specifications, plans, and implementation tasks.

Before continuing, explain the difference between:

- **Specification:** What the feature must do and how success will be judged.
- **Plan:** How the feature will be built.
- **Tasks:** The ordered work needed to execute the plan.
