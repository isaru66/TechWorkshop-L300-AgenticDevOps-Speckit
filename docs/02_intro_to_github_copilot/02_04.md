# Task 04 - Review the result

## Introduction

Review follows the build. Generated code may compile while still having
incorrect controls, unfair collision boxes, or broken restart behavior.

## Description

Play Copilot Flappy, inspect the changes against the approved plan, and ask
Copilot for focused fixes where needed.

## Success Criteria

- The game passes the manual checks below and its production build succeeds.
- You can explain how the mascot asset, input, scoring, and restart work.
- Deviations or unresolved issues are recorded rather than silently accepted.

## Learning Resources

- [Review AI-generated code edits in VS Code](https://code.visualstudio.com/docs/agents/run/review-code-edits)
- [Review changes in Git](https://git-scm.com/docs/git-diff)

## Key Tasks

1. Review the changed files in VS Code's **Source Control** view. Confirm
   changes stay in `src/copilot-flappy/`, the supplied mascot source is
   unchanged, and there are no secrets or unexpected dependencies.
2. Run the following acceptance checks in the browser. Record pass/fail and
   any reproduction steps.

   | Check | Expected result |
   | --- | --- |
   | First load | Ready screen shows instructions and a start action; gameplay waits for start |
   | Mascot | One recognizable Copilot pose appears, not the full sheet, an emoji, or a stretched image |
   | Keyboard | Space produces one flap per press and does not scroll the page |
   | Pointer | Clicking or tapping the play area produces one flap, not duplicate touch/click flaps |
   | Gravity | Without input, the mascot falls |
   | Obstacles | Pairs scroll toward the player with varied, reachable gaps |
   | Score | Passing one pair adds exactly one point, never several |
   | Collision | Contact with either obstacle, the ceiling, or the ground ends play; clear gaps do not |
   | Game over | Final score is shown and gameplay stops until restart |
   | Restart | Score, position, obstacles, and timers reset; repeat three times without speed or input duplication |
   | Small screen | At a mobile-sized viewport, instructions, controls, score, and play area remain usable |
   | Asset failure | Temporarily block the mascot image request with browser developer tools and reload; a visible error appears rather than an invisible player; unblock and reload afterward |
   | Console | No uncaught errors during start, play, game over, or restart |

   Use a real touch device for the tap check when available, or browser touch
   emulation. Record the device or emulation used and any untested cases.

3. From the game folder, run:

   ```shell
   npm run build
   ```

   Confirm it exits successfully. Treat build output and browser behavior as
   separate evidence.
4. If a check fails, describe the observed behavior precisely. For example:

   ```text
   After restarting three times, a single Space press makes the mascot
   jump farther than on the first run. Expected: the same flap strength
   on every run. Inspect input-handler and animation-loop lifecycle,
   fix the root cause without changing the approved game scope, rerun
   the build, and report which checks need to be repeated.
   ```

5. Review the fix and repeat the failed checks plus related behavior checks.
   Stop the development server when finished.

## Reflection

- Which details in the plan prevented unnecessary implementation work?
- How did supplying the mascot image improve the result?
- What did manual play reveal that the production build did not?

You have completed a **Plan -> Build -> Review** cycle with GitHub Copilot.
