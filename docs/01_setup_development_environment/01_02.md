# Task 02 - Install prerequisite software

## Introduction

{: .warning }
> A GitHub Codespace supplies both backend toolchains and the shared tools. Skip the installation commands, but verify the tools for your chosen backend and the shared tools. If your Codespace predates this setup, run **Codespaces: Rebuild Container** from the Command Palette first; see [Task 01]({% link docs/01_setup_development_environment/01_01.md %}).

## Description

For local development, choose one backend for exercises 03-04:

{% capture java %}
Install [JDK 21 and Maven 3.9](#java-prerequisites); the .NET SDK is not required.
{% endcapture %}
{% capture dotnet %}
Install the [.NET 10 SDK](#dotnet-prerequisites); Java and Maven are not required.
{% endcapture %}
{% include stack-tabs.html id="setup-backend-prerequisites" label="Backend prerequisites" java=java dotnet=dotnet %}

Both paths use Git, VS Code, Node.js, Python, uv, the Specify CLI, and Docker with Docker Compose for PostgreSQL. Continue through the [shared prerequisites](#shared-prerequisites) after installing your selected backend tools.

For the Java path, Spring Boot 4.1.x requires **Java 17 or later** and supports **Maven 3.6.3 or later**, according to its [official system requirements](https://github.com/spring-projects/spring-boot/blob/4.1.x/documentation/spring-boot-docs/src/docs/antora/modules/ROOT/pages/system-requirements.adoc). The workshop uses **JDK 21** and **Maven 3.9** to match the devcontainer; Java 21 is the workshop version, not Spring Boot's minimum requirement.

## Success Criteria

- Your selected backend toolchain and the shared tools are installed and verified.
- Docker and Docker Compose are available for the PostgreSQL exercise.

## Key Tasks

### 01: Install Java JDK 21 (Java path only)
{: #java-prerequisites }

Install a **JDK**, not just a Java runtime, so that you can compile and run the Spring Boot application. Use JDK 21 to match the devcontainer.

<details markdown="block">
<summary><strong>Expand this section to view the solution</strong></summary>

Download and install a JDK 21 distribution for your operating system:

- [Microsoft Build of OpenJDK 21](https://learn.microsoft.com/en-us/java/openjdk/download) (recommended)
- [Eclipse Temurin 21 JDK](https://adoptium.net/temurin/releases/?version=21) (alternative)

{% capture windows %}
Install Microsoft Build of OpenJDK 21:

```powershell
winget install -e --id Microsoft.OpenJDK.21
```

Set `JAVA_HOME` to the JDK installation directory and add its `bin` directory to your `PATH` using Windows environment variables.
{% endcapture %}
{% capture macos %}
Download the Microsoft Build of OpenJDK 21 macOS installer for your Mac's architecture from the link above.

After installation, select JDK 21 for the current terminal:

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
export PATH="$JAVA_HOME/bin:$PATH"
```

Add these settings to your shell profile if needed for future terminals.
{% endcapture %}
{% capture linux %}
**GitHub Codespaces:** JDK 21 is already installed. Use the verification commands below; no installation is needed.

**Local Linux:** Install JDK 21 using the distribution-specific instructions on the Microsoft or Temurin download page above. Set `JAVA_HOME` to the installation directory and add its `bin` directory to `PATH`.
{% endcapture %}
{% include os-tabs.html id="jdk-install" label="JDK installation" windows=windows macos=macos linux=linux %}

Open a new terminal and verify:

```bash
java --version
javac --version
```

Both commands should report version `21.x`.

</details>

### 02: Install Maven 3.9 (Java path only)

Maven is used to build and test the Java backend. Use Maven 3.9 to match the devcontainer.

<details markdown="block">
<summary><strong>Expand this section to view the solution</strong></summary>

{% capture windows %}
Download the **Maven 3.9.x binary ZIP archive** from the [Apache Maven downloads page](https://maven.apache.org/download.cgi). Extract it and add its `bin` directory to your Windows `PATH`, following the [installation instructions](https://maven.apache.org/install.html).
{% endcapture %}
{% capture macos %}
Download a **Maven 3.9.x binary archive** from the [Apache Maven downloads page](https://maven.apache.org/download.cgi). Extract it and add its `bin` directory to your shell's `PATH`, following the [installation instructions](https://maven.apache.org/install.html).
{% endcapture %}
{% capture linux %}
**GitHub Codespaces:** Maven 3.9 is already installed. Continue with verification.

**Local Linux:** Download a **Maven 3.9.x binary archive** from the [Apache Maven downloads page](https://maven.apache.org/download.cgi). Extract it and add its `bin` directory to your shell's `PATH`, following the [installation instructions](https://maven.apache.org/install.html).
{% endcapture %}
{% include os-tabs.html id="maven-install" label="Maven installation" windows=windows macos=macos linux=linux %}

Open a new terminal and verify:

```bash
mvn --version
```

The output should report Maven `3.9.x` and Java `21.x`. If Maven reports a different Java version, check `JAVA_HOME`.

</details>

### 03: Install the .NET 10 SDK (.NET path only)
{: #dotnet-prerequisites }

Install the **.NET 10 SDK**, not just a runtime, to build and run the ASP.NET Core backend. The SDK includes the corresponding runtimes.

<details markdown="block">
<summary><strong>Expand this section to view the solution</strong></summary>

{% capture windows %}
Use the [Microsoft Windows installation instructions](https://learn.microsoft.com/en-us/dotnet/core/install/windows) to install the .NET 10 SDK with WinGet:

```powershell
winget install -e --id Microsoft.DotNet.SDK.10
```

Alternatively, download the **SDK** installer for your Windows architecture from the [.NET 10 downloads page](https://dotnet.microsoft.com/en-us/download/dotnet/10.0).
{% endcapture %}
{% capture macos %}
From the [.NET 10 downloads page](https://dotnet.microsoft.com/en-us/download/dotnet/10.0), download the **SDK** macOS installer: Arm64 for Apple silicon or x64 for an Intel Mac. Open the installer and follow its prompts. See the [Microsoft macOS installation instructions](https://learn.microsoft.com/en-us/dotnet/core/install/macos).
{% endcapture %}
{% capture linux %}
**GitHub Codespaces:** The .NET 10 SDK is installed in the container. Continue with verification.

**Local Linux:** Follow [Microsoft's Linux installation guide](https://learn.microsoft.com/en-us/dotnet/core/install/linux) for your distribution, release, and architecture. Configure the appropriate package source and select the **.NET 10 SDK**, not a runtime-only package. Package sources and commands differ by distribution.

For Ubuntu, after configuring the appropriate source as described in the [Ubuntu instructions](https://learn.microsoft.com/en-us/dotnet/core/install/linux-ubuntu-install), install the version-specific SDK package:

```bash
sudo apt-get update
sudo apt-get install -y dotnet-sdk-10.0
```

For other distributions, use their linked instructions rather than assuming these Ubuntu commands apply.
{% endcapture %}
{% include os-tabs.html id="dotnet-sdk-install" label=".NET 10 SDK installation" windows=windows macos=macos linux=linux %}

Open a new terminal and verify:

```bash
dotnet --list-sdks
dotnet --info
```

The SDK list must include a non-preview version beginning with `10.0.` (for example, `10.0.100`), even if other SDKs are also installed. `dotnet --info` shows the selected SDK and environment; it can select another installed SDK depending on the workspace. If 10.0 is missing, check the installed architecture and the `dotnet` executable on your `PATH`.

</details>

### 04: Install Node.js
{: #shared-prerequisites }

Use Node.js 22 to match the devcontainer. npm is included with Node.js.

<details markdown="block">
<summary><strong>Expand this section to view the solution</strong></summary>

Download and install **Node.js 22.x** from the [official downloads page](https://nodejs.org/en/download/). Select version 22 explicitly rather than a newer default LTS version.

Choose the instructions for your operating system:

{% capture windows %}
Download a Windows installer for **Node.js 22.x** from the [official Node.js 22 release directory](https://nodejs.org/dist/latest-v22.x/), choosing the installer for your architecture.
{% endcapture %}
{% capture macos %}

```bash
brew install node@22
```

Follow Homebrew's printed instructions to add Node.js 22 to your `PATH`.
{% endcapture %}
{% capture linux %}
**GitHub Codespaces:** Node.js 22 and npm are already installed. Continue with verification.

**Local Linux (Debian/Ubuntu via NodeSource):**

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs
```

{% endcapture %}
{% include os-tabs.html id="node-install" label="Node.js installation" windows=windows macos=macos linux=linux %}

Verify the installation:

```bash
node --version
npm --version
```

Node.js should report a version of `v22.x.x`.

</details>

### 05: Install Python

Python 3.11 or later is required. Version 3.14 is recommended.

<details markdown="block">
<summary><strong>Expand this section to view the solution</strong></summary>

Download and install Python from the [official downloads page](https://www.python.org/downloads/). Make sure to check the **Add Python to PATH** option during installation on Windows.

{% capture windows %}

```powershell
winget install -e --id Python.Python.3.14
```

Verify the installation:

```powershell
python --version
```

{% endcapture %}
{% capture macos %}

```bash
brew install python@3.14
```

Follow Homebrew's printed PATH instructions, then verify:

```bash
python3 --version
```

{% endcapture %}
{% capture linux %}
**GitHub Codespaces:** Python is supplied by the container OS. Skip installation and verify it below.

**Local Linux (Debian/Ubuntu):**

```bash
sudo apt-get update
sudo apt-get install -y python3 python3-pip python3-venv
```

Verify the installation:

```bash
python3 --version
```

{% endcapture %}
{% include os-tabs.html id="python-install" label="Python installation and verification" windows=windows macos=macos linux=linux %}

Confirm that the version is `3.11.x` or later. If your Linux distribution provides an older version, install a supported Python version before continuing.

</details>

### 06: Install uv and the Spec Kit Specify CLI

uv manages the Specify CLI installation. The devcontainer installs uv and runs the Specify CLI installation automatically through `postCreateCommand`; local users must run it themselves.

<details markdown="block">
<summary><strong>Expand this section to view the solution</strong></summary>

Install uv using the [official installation instructions](https://docs.astral.sh/uv/getting-started/installation/).

{% capture windows %}

```powershell
winget install -e --id astral-sh.uv
```

{% endcapture %}
{% capture macos %}

```bash
brew install uv
```

{% endcapture %}
{% capture linux %}
**GitHub Codespaces:** uv and the Specify CLI are already installed. Skip the installation commands and run the verification commands below.

**Local Linux:**

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

{% endcapture %}
{% include os-tabs.html id="uv-install" label="uv installation" windows=windows macos=macos linux=linux %}

Open a new terminal and verify:

```bash
uv --version
```

**Local installations only:** With Git installed and available on your `PATH` from the repository setup task, install the same Specify CLI release as the devcontainer. Skip this step in GitHub Codespaces.

```bash
uv tool install --force specify-cli --from git+https://github.com/github/spec-kit.git@v1.2.6
uv tool update-shell
```

Open a new terminal and verify:

```bash
specify version
```

Installing the CLI does not initialize Spec Kit in your repository. You will initialize your workspace in Exercise 03.

</details>

### 07: Install Visual Studio Code and extensions

Visual Studio Code is the recommended editor for this workshop. Install the extensions for your chosen backend and the shared extensions below. The devcontainer includes both backend sets.

<details markdown="block">
<summary><strong>Expand this section to view the solution</strong></summary>

{% capture windows %}
Download and install Visual Studio Code for Windows from the [official downloads page](https://code.visualstudio.com/download). Enable the installer's **Add to PATH** option to use the `code` command.
{% endcapture %}
{% capture macos %}
Download and install Visual Studio Code for macOS from the [official downloads page](https://code.visualstudio.com/download). In the Command Palette, run **Shell Command: Install 'code' command in PATH** to enable the terminal command.
{% endcapture %}
{% capture linux %}
**GitHub Codespaces:** VS Code and the extensions listed below are already configured. No installation is needed.

**Local Linux:** Install the appropriate package from the [official downloads page](https://code.visualstudio.com/download).
{% endcapture %}
{% include os-tabs.html id="vscode-install" label="Visual Studio Code installation" windows=windows macos=macos linux=linux %}

For local installations, open VS Code and use the Extensions Marketplace (`Ctrl+Shift+X`, or `Command+Shift+X` on macOS), or run the commands below.

**Java path only:**

- **Extension Pack for Java** (`vscjava.vscode-java-pack`)
- **Spring Boot Extension Pack** (`vmware.vscode-boot-dev-pack`)

```bash
code --install-extension vscjava.vscode-java-pack
code --install-extension vmware.vscode-boot-dev-pack
```

**.NET path only:**

- **C#** (`ms-dotnettools.csharp`)

```bash
code --install-extension ms-dotnettools.csharp
```

**Both paths:**

- **GitHub Copilot** (`GitHub.copilot`)
- **GitHub Copilot Chat** (`GitHub.copilot-chat`)
- **REST Client** (`humao.rest-client`)
- **PostgreSQL** (`ms-ossdata.vscode-pgsql`)

```bash
code --install-extension GitHub.copilot
code --install-extension GitHub.copilot-chat
code --install-extension humao.rest-client
code --install-extension ms-ossdata.vscode-pgsql
```

</details>

### 08: Install Docker and Docker Compose

Both backend paths use a Docker runtime and Docker Compose for the local PostgreSQL exercise. On Windows or macOS, choose Docker Desktop or Rancher Desktop; on Linux, use Docker Engine and the Compose plugin.

<details markdown="block">
<summary><strong>Expand this section to view the solution</strong></summary>

{% capture windows %}
Install [Docker Desktop](https://www.docker.com/products/docker-desktop/):

```powershell
winget install -e --id Docker.DockerDesktop
```

Alternatively, install [Rancher Desktop](https://rancherdesktop.io/):

```powershell
winget install -e --id suse.RancherDesktop
```

Start your chosen application and ensure the Docker engine is running. For Rancher Desktop, select the **dockerd (moby)** engine.
{% endcapture %}
{% capture macos %}
Install [Docker Desktop](https://www.docker.com/products/docker-desktop/):

```bash
brew install --cask docker
```

Alternatively, download [Rancher Desktop](https://rancherdesktop.io/) and select the **dockerd (moby)** engine. Start your chosen application before verification.
{% endcapture %}
{% capture linux %}
**GitHub Codespaces:** Docker-in-Docker and Docker Compose v2 are preconfigured. Do not install Docker Desktop inside the Codespace.

**Local Linux:** Follow the instructions for [Docker Engine](https://docs.docker.com/engine/install/) and the [Docker Compose plugin](https://docs.docker.com/compose/install/linux/) for your distribution. Ensure the engine is running and accessible to your user before verification.
{% endcapture %}
{% include os-tabs.html id="docker-install" label="Docker installation" windows=windows macos=macos linux=linux %}

Verify the installation:

```bash
docker --version
docker compose version
docker info
```

Docker Compose should report `v2.x`, and `docker info` should connect to the running engine without errors. PostgreSQL itself is created later using Compose; it is not installed as a devcontainer feature.

</details>
